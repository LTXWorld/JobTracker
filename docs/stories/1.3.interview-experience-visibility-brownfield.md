## Story
**As a** 维护岗位状态的求职者，  
**I want** 在查看时间轴或状态详情时能够看到每次面试流转记录下来的体验反馈，  
**so that** 我可以快速回顾各轮面试的感受与备注，辅助后续决策与复盘。

## Acceptance Criteria
1. 当状态历史节点的 `metadata.interview_experience.skip=false` 时，时间轴展示对应的评分（good/average/bad 映射为中文标签）、备注与记录时间；若存在 `note`、`recorded_at`，均以用户可读格式显示。
2. 当状态历史节点的 `metadata.interview_experience.skip=true` 时，时间轴显式标识“已跳过反馈”，并在存在 `skip_reason` 或 `note` 时显示说明；该展示同时适用于状态详情弹窗共享的时间轴。
3. Pinia `convertToTimelineData` 与 `StatusTimelineItem` 类型扩展保留 `interview_experience` 完整结构，刷新或重新拉取历史后即可立即看到最新反馈，无需手动重载页面。
4. 补充或更新前端自动化测试覆盖“记录反馈”“跳过反馈”两类场景，验证时间轴渲染内容与数据整形逻辑，现有测试套件通过。

## Dev Notes
### 现有数据流
- `getStatusHistory` 已将后端返回的 `metadata` 透传给前端，包含 `interview_experience` 字段；顺序按时间升序排列，缓存于 Pinia `statusHistories` 映射中。[Source: frontend/src/api/statusTracking.ts:26]
- 状态更新成功后会调用 `fetchStatusHistory` 刷新缓存，并驱动时间轴重渲染；详情弹窗与主界面共用该数据源。[Source: frontend/src/stores/statusTracking.ts:238]

### UI 组件现状
- `StatusTimeline.vue` 目前仅展示状态标签、停留时长、面试安排和备注，缺少体验反馈可视化。[Source: frontend/src/components/StatusTimeline.vue:114]
- 状态详情弹窗通过子组件方式复用时间轴，因此一处修复可覆盖两处展示。[Source: frontend/src/components/StatusDetailModal.vue:47]

### 类型定义与 Store
- `StatusTimelineItem` 类型未包含体验反馈字段，需新增结构以避免松散的 `metadata` 取值。[Source: frontend/src/types/index.ts:511]
- `convertToTimelineData` 返回项中可注入新增字段（例如 `interviewExperience`），同时保留 `note` 等现有属性。[Source: frontend/src/stores/statusTracking.ts:362]

### 面试体验数据形态
- 后端在状态流转事务内写入规范化的体验数据，字段包括 `rating`、`note`、`skip`、`skip_reason`、`recorded_at`、`recorded_by`、`from_status`、`to_status` 等；缺省请求会自动生成 `skip=true` 记录。[Source: backend/internal/service/status_tracking_service.go:780]
- API 文档列举了携带体验的请求样例，可参考其字段语义确保前端展示文案一致。[Source: docs/api/README.md:120]

### 兼容与刷新策略
- 未携带 `interview_experience` 的历史节点仍需沿用原展示逻辑，避免布局抖动；新增展示应具备可选渲染。
- 需要保证 `refreshTimeline` 与 `watch` 逻辑在新增字段后依旧稳定，防止计算属性缓存失效或动画异常。

### Testing
- 前端测试基于 Vitest + Vue Test Utils / Testing Library，在 `frontend` 目录运行 `pnpm test` / `npm run test` 即可；时间轴组件测试应使用 `happy-dom` 或 `jsdom` 环境。[Source: frontend/package.json]
- 建议为 Pinia store 使用 `setActivePinia(createPinia())` 初始化测试环境，确保转换函数可独立验证。
