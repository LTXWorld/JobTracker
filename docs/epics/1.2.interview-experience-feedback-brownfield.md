# 面试体验标记增强 - Brownfield Enhancement

## Epic Goal

在现有岗位状态流转体系中，为处于面试流程的岗位补充“上一轮面试体验打分”能力，确保用户在推进下一轮状态前主动记录体验反馈，从而沉淀后续分析数据并帮助用户复盘求职策略。

## Epic Description

### Existing System Context

- 当前相关功能：状态更新由 `backend/internal/service/status_tracking_service.go` 负责事务校验与历史写入，前端通过 `frontend/src/stores/statusTracking.ts` 调用状态更新接口；面试阶段状态枚举定义在 `backend/internal/model/job_application.go`。
- 现有技术栈：前端 Vue 3 + Pinia + Ant Design Vue，后端 Go + PostgreSQL，状态历史通过 JSONB 存储元数据。
- 主要集成点：状态更新 API `/api/v1/applications/{id}/status`，状态历史记录写入逻辑，前端拖拽/表单更新流程以及提醒中心的状态变更追踪。

### Enhancement Details

- 变更内容：在用户尝试将岗位从某一“进行中面试状态”（如“`一面中`”）推进至下一阶段或终态前，弹出模态框提示用户对刚完成的面试轮次进行体验评价（好 / 一般 / 差，可选填备注）；评价成功提交后才继续后续状态更新，若用户取消则中止状态变更。
- 集成方式：前端在触发 `UpdateStatusRequest` 前捕获面试状态转换，调用新增的评价 API 或将评价数据随状态更新请求一并传递；后端在更新事务中验证面试评价（可选但建议必填），并将结果写入状态历史元数据或独立的 `interview_experiences` 表，同时为后续统计接口预留聚合字段。
- 成功标准：90% 以上发生面试状态转换的操作能记录到有效评价；后续仪表盘或时间线可以展示该历史记录，为用户提供面试体验总结。

### Stories

1. **后端：面试体验数据模型与 API 扩展** —— 增加面试体验评分的存储结构、更新 `StatusTrackingService` 校验逻辑，并在状态历史或独立表中写入评价数据，提供读取接口。
2. **前端：状态更新流程加入面试体验模态** —— 在状态拖拽或表单更新时识别面试阶段转换，弹出评价模态并将选择结果与备注注入状态更新请求。
3. **体验展示与提醒联动** —— 在时间线/状态历史视图中展示面试体验结果，并为提醒中心或通知栏提供复盘提示（可作为轻量显示，未来可扩展为统计图表）。

## Compatibility Requirements

- [ ] 现有 API 兼容未携带面试体验评价的请求（需默认走旧流程）。
- [ ] 数据库 schema 的新增字段需保持向后兼容（允许空值并设置安全默认值）。
- [ ] 前端 UI 遵循现有 Ant Design Vue 设计体系，保证风格一致。
- [ ] 性能影响可控，不显著增加状态更新接口的响应时间。

## Risk Mitigation

- **主要风险**：强制评价可能增加操作阻力，导致用户放弃提交或产生负面体验。
- **风险缓解**：通过清晰的文案和“稍后补记”选项降低阻塞感；若选择跳过需记录原因，后续引导补充。
- **回滚计划**：保持状态更新 API 接口向后兼容，可通过特性开关（环境变量）快速关闭前端提示并忽略后端评价校验。

## Definition of Done

- [ ] 全量故事完成并通过验收，评价数据在数据库中可查询。
- [ ] 状态更新及历史功能回归测试通过，确保未引入回归问题。
- [ ] 面试体验评价在前端时间线或详情页可视化展示。
- [ ] 文档（API 说明、用户指南）更新说明新增评价步骤。
- [ ] 指标与监控补充评价完成率等关键数据。
