# 记录投递插件 路线图与实施规划（Roadmap）

## 阶段划分
- P0（地基夯实，1–2 天）
  - 打通扩展与后端“创建投递记录”API（`POST /api/v1/applications`）。
  - 插件设置中新增“默认企业属性 company_attribute”。
  - Popup 中增加“记录本页职位”按钮，最小表单提交通路。

- P1（MVP，1–1.5 周）
  - 站点适配 v1：zhaopin.com、51job.com、zhipin.com、mokahr.com。
  - Content Script 提供职位解析与确认弹窗（必填可编辑）。
  - 去重策略与提示（URL/公司/职位/日期）。
  - 离线队列与自动重试（基础版）。
  - 基本埋点：解析成功/失败、提交成功/失败。

- P2（易用性与鲁棒性，0.5–1 周）
  - 训练模式：用户可点选页面元素建立字段映射（已具备基础能力，整合入口与 UX）。
  - 更多站点适配与兜底改进；
  - 错误提示与回滚、日志收敛；
  - 插件内“最近记录成功的投递”列表与跳转。

- P3（优化与扩展，按需）
  - 后端模糊查重与幂等键支持；
  - 邮箱解析/移动分享入口；
  - 本地加密与更细的隐私控制；
  - 远端适配器配置热更新（灰度）。

## 任务拆分与负责人建议
- 扩展/前端（1人）
  - 解析 UI 与确认弹窗、Popup 设置、训练模式入口、适配器实现、消息通道。
- 后端（1人）
  - 接口契约核对、必要字段校验优化、（可选）查重/幂等、监控与速率限制。
- 测试/验收（0.5人）
  - 跨站点 E2E 用例、弱网/离线/未登录等异常场景、浏览器兼容。

## 里程碑与交付件
- M0：技术方案评审通过（本目录文档）。
- M1：MVP 可手动触发记录（Popup 最小表单），可成功写入后台；
- M2：4 站点自动解析+确认提交；
- M3：离线队列/去重/基础埋点稳定，发布 Beta；
- M4：训练模式可用，适配率提升，发布 v1.0。

## 验收标准（与分析文档一致补充）
- P1 结束：
  - 4 站点解析正确率 ≥ 80%，提交成功率 ≥ 95%；
  - 解析失败时弹出最小表单可完成提交；
  - 未登录/离线路径可恢复并补交；
  - 去重提示明确且可选择。

## 风险与应对
- 站点改版：适配器优先级与回退策略；保留“训练模式”作为救援手段。
- 字段必填失败：插件设置提供默认 company_attribute；确认弹窗强校验。
- CORS/鉴权：沿用现有配置与刷新机制，联调专项用例验证。

## 发布与回滚
- 发布：
  - 内部 CRX 侧载 → 小范围灰度 → Chrome Web Store 上架（如需）。
- 回滚：
  - 版本化适配器；
  - 关闭站点开关或退回到“仅最小表单”模式；
  - 后端接口保持向后兼容。
