# Project Brief: JobView

## 引言
本文档在互动模式下编制，旨在为 JobView 求职投递管理平台提供全局概览，支撑后续 PRD、路线图与跨团队协作。内容覆盖产品定位、用户画像、目标指标、MVP 范围、技术考量、风险评估与后续行动建议。

## 执行摘要
JobView 是一款面向求职者与招聘协作团队的多端（Web、移动端、浏览器扩展）投递管理平台，提供从岗位收集、状态跟踪到提醒通知、数据分析的闭环体验。平台主打职位状态拖拽、时间线追踪、提醒中心与数据洞察等能力，帮助用户系统掌握投递进度、即时响应关键节点并提升整体求职效率。

## 问题陈述
当前求职者常依赖表格或零散记录来管理投递，难以直观掌握多岗位的阶段进展、反馈节点和提醒事项。随着岗位数量增加，手动整理导致遗漏面试、重复投递、错过跟进时机等痛点。通用工具缺乏面向求职场景的状态模板、自动提醒、时间线汇总与数据分析，也难以兼顾多端同步和第三方表单填写需求。因此需要一个围绕“投递状态流转”和“进度可视化”构建的专用平台，帮助个人或团队高效维护招聘流程。

## 方案概述
JobView 以“跨端、可视化的投递管理中心”为定位：Web 端提供拖拽看板、时间线和提醒中心，Go 后端支持状态机、数据分析和邮箱集成，Chrome 扩展解决跨平台填写效率，React Native 客户端承载移动场景。相较通用表格和项目管理工具，JobView 提供结构化状态模板、自动化提醒、邮件事件关联与投递数据洞察，帮助用户可靠掌握岗位进展并及时响应。

## 目标用户

### 主要用户细分：高强度求职者（个人）
- **画像**：大城市 1-5 年经验的年轻职场人或转岗者，活跃于竞争激烈行业。
- **行为特征**：并行维护 10-30 个岗位，跨多招聘平台投递，常在夜晚或碎片时间回顾。
- **核心痛点**：缺少统一“投递进度驾驶舱”，提醒易遗漏，表格对求职字段支持不足。
- **主要目标**：掌握各岗位阶段、及时跟进、沉淀数据洞察提升策略。
- **关键需求**：拖拽状态管理、集中提醒、跨设备同步、自定义字段、可视化分析、自动填表。

### 次级用户细分：临近毕业的大学生与研究生
- **画像**：大四本科生、研二研三学生，处于校招高峰，信息来源分散。
- **行为特征**：短期内密集投递、准备笔试面试、同步测评链接，频繁在移动/公共设备切换。
- **核心痛点**：节点密集易遗漏、渠道多难同步、重复填写简历耗时。
- **主要目标**：高效管理多岗位、抢占面试测评时效、与同伴共享信息、复盘投递数据。
- **关键需求**：跨端同步、批量拖拽、提醒与日历整合、快捷填表、校招特有字段支持。

## 目标与成功指标

### 业务目标
- 构建跨端统一的求职投递管理平台，上线 6 个月内达到 5,000 名活跃用户，月活率 ≥ 40%。
- 通过状态拖拽、提醒、数据分析提升效率，使 75% 用户认为“流程透明度提升”。
- Chrome 扩展和移动端各实现 100+ 安装，验证跨入口协同价值。

### 用户成功指标
- 单用户活跃岗位平均 ≥ 12 个。
- 关键提醒完成率（24 小时内）≥ 85%。
- Chrome 扩展填表成功率 ≥ 90%，跨端同步延迟 ≤ 5 分钟。

### 关键绩效指标（KPI）
- 月新增投递记录 ≥ 15,000 条。
- 用户平均每周状态拖拽 ≥ 10 次。
- 提醒触发响应率 ≥ 70%。
- 数据仪表盘月访问 ≥ 2,000 次。
- 多端活跃率：≥ 40% 活跃用户同时使用两种以上入口。

## MVP 范围

### 核心特性（Must Have）
- **投递记录管理与状态拖拽**：支持岗位创建、编辑、删除与自定义流程拖拽。
- **提醒与时间线中心**：集中管理提醒、面试节点并可按时间线追溯历史。
- **Chrome 自动填表扩展**：从 JobView 简历快速填充主流招聘网站表单。
- **基础数据仪表盘**：提供投递量、转化率等核心图表。
- **Go 后端与 Vue Web 前端**：提供 API、身份认证、状态机逻辑与交互界面。

### 超出范围
- 多租户/团队权限管理。
- 自动邮箱同步的高级调度与规则。
- 深度 AI 分析（成功率预测等）。
- 完整移动端业务（暂定位轻量浏览）。
- 开放平台与第三方生态集成。

### MVP 成功标准
- Web 端完成岗位录入到状态更新的闭环。
- 提醒覆盖 ≥80% 关键节点，减少手工清单依赖。
- Chrome 扩展支持 ≥3 个招聘站点，真实场景成功率 ≥85%。
- 仪表盘提供基础趋势，辅助识别高价值渠道或阶段。

## Post-MVP 愿景

### Phase 2 功能
- 强化邮箱事件自动解析与状态同步调度。
- 扩展统计视图的自定义配置与导出能力。
- 完善移动端投递 CRUD、提醒处理与离线缓存。
- 拓展 Chrome 扩展适配站点并提供字段映射向导。

### 长期愿景
- 打造支持团队协作的跨端平台，引入角色权限管理。
- 引入智能分析模块，输出投递成功率预测与渠道推荐。
- 实现 Web、移动、第三方生态的实时数据一致性。

### 扩展机会
- 面向高校/培训机构的定制版，内置校招日历与群发通知。
- 提供开放 API/Webhook，对接企业 ATS、CRM。
- 增值服务：职业教练协作、简历优化建议、集成市场。

## 技术考量
- **目标平台**：Web（主流桌面浏览器）、React Native 移动端（iOS 14+/Android 11+）、Chrome MV3 扩展；核心接口 P95 < 300ms，拖拽延迟 < 150ms，跨端同步 ≤ 5 分钟。
- **技术偏好**：前端 Vue 3 + TypeScript + Vite + Ant Design Vue + Pinia + Vuedraggable + Vue ECharts；后端 Go 1.24 + Gin/Gorilla Mux + GORM + JWT + cron；数据库 PostgreSQL 12+，可视需要引入 Redis、消息队列；Docker Compose/K8s 部署，前端通过 Vite 代理 `/api`。
- **架构注意点**：单仓多模块结构（backend/frontend/mobile/extension/docs）；短期以内嵌状态机的单体后端为主，预留邮箱同步、通知模块服务化接口；扩展与移动端通过标准 API 集成；必须保障 HTTPS、JWT 秘钥轮换、邮箱凭证加密，遵循 GDPR/PIPL 要求。

## 约束与假设

### 约束
- **预算**：以个人或小型团队自筹为主，采用开源栈与自部署；商业化需额外云资源与合规投入。
- **时间**：MVP 目标 3-4 个月内交付，Chrome 扩展与移动端补强在后续 1-2 个迭代推进。
- **资源**：团队以全栈工程师为核心，缺乏专职运维与安全人手，需依赖脚本化部署与自动化监控。
- **技术**：Go + Vue + PostgreSQL 为主栈，要求具备跨端开发能力；需应对邮箱同步与浏览器规范更新。

### 关键假设
- 用户愿意在 Web 端维护数据并安装 Chrome 扩展以换取效率。
- 邮箱与招聘平台接口短期稳定，或团队具备快速适配能力。
- Docker + GitHub Actions 流水线可在目标环境顺利执行。
- 本地化部署与自管密钥能满足数据安全与隐私诉求，如进军企业市场需追加合规投入。

## 风险与开放问题

### 关键风险
- 外部接口变动导致自动填表或邮件解析失效。
- 数据安全与隐私管理不到位引发泄露风险。
- 多端同步差异造成体验不一致、降低用户信任。
- 团队资源有限，跨模块并行迭代可能拖慢交付节奏。

### 开放问题
- 用户增长渠道与首批种子用户获取策略。
- 付费模式与订阅定位，免费与团队版的功能边界。
- 邮箱同步范围是否支持更多本地或企业邮箱。
- 团队协同能力的优先级及对路线图的影响。

### 待调研领域
- 校招用户的细分需求与特有字段。
- 优先适配的招聘平台清单与字段差异。
- 各邮箱服务商的速率限制、授权流程及监管要求。
- 与 HR 工具、培训机构或猎头的潜在合作模式。
